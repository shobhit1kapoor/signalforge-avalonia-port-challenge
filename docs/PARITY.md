# Terminal2 and SIGNALFORGE parity inventory

Status is conservative and current as of 2026-10-23. **Implemented** means the capability is present in Core or the desktop app and has relevant automated verification. **Partial** means important workflow, UI integration, runtime proof, or edge behavior is missing. **Not started** means no implementation exists. Passing a build alone does not prove a capability.

## Verification record

- `dotnet restore SignalForge.slnx --locked-mode`: passed on Windows and Ubuntu 26.04 under WSL2.
- `dotnet build SignalForge.slnx --configuration Release --no-restore`: passed on Windows and Ubuntu 26.04 under WSL2 with 0 warnings and 0 errors.
- Windows: the 260-test suite excluding `Terminal2SendWorkflowViewModelTests` passed, and that workflow passed in isolation (261 total). The combined invocation exceeded the 3-minute inactivity limit at that workflow.
- Ubuntu 26.04 under WSL2: the same 260+1 split passed (261 total). The combined run fails at the Avalonia dispatcher with a thread-ownership exception. CI uses the verified split with a 3-minute VSTest hang diagnostic.
- The v0.1.0 hosted release workflow built and launched self-contained Windows x64, Linux x64, and native macOS ARM64 packages on their corresponding runners, then published them with a SHA-256 manifest. Local Windows and WSL2/Xvfb Linux packages also remained open through the 12-second smoke window. The downloaded release packages passed manifest checksum verification and archive-content checks. Platform limits are in `docs/evidence/verification-2026-10-23.md` and hashes are in `artifacts/SHA256SUMS.txt`.
- `dotnet list SignalForge.slnx package --vulnerable --include-transitive`: no vulnerable packages reported by the current NuGet source (prior verification).
- These checks establish builds, the automated test suite, application startup on all three hosted target platforms, and the public v0.1.0 release. Windows UI checks additionally cover the current dock workspace, interactive local PowerShell PTY, a passing simulator test, and a deliberately corrupted Modbus function-code failure. They do not establish every interactive workflow, physical hardware, or local bare-metal Linux behavior.
